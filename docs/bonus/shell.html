2 Other shell wildcards

In the first session on working with files in the Unix shell, you learned about globbing (selecting files) with the * wildcard. While not as frequently used as *, a few other shell wildcards exist. Here is a complete overview of shell wildcards:

Wildcard Matches
* Any number of any character, including nothing
? Any single character
[] and [^] One or none (^) of the “character class” within the brackets

To get set up, create some dummy FASTQ files to practice with:

# (You should be in /fs/ess/PAS2880/users/$USER/week03/sandbox)
touch sample1_R1.fastq sample1_R2.fastq
touch sample2_R1.fastq sample2_R2.fastq
touch sample3_R1.fastq sample3_R2.fastq

Using the more restrictive wildcard ? can be useful to prevent accidental matches. Here is an example of using the ? wildcard to match both R1 and R2:

ls sample1_R?.fastq
sample1_R1.fastq  sample1_R2.fastq

The character class wildcard [] can be useful when you want to include or exclude multiple files among a set of files with rather similar names. For example, to match files for sample1 and sample2 using only a character class with []:

  • Method 1 – List all possible characters (1 and 2 in this case):

    # This is saying: after 'sample', there should be a 1 OR a 2 ('[12]'),
# followed by any character (*):
ls sample[12]*
    sample1_R1.fastq  sample1_R2.fastq  sample2_R1.fastq  sample2_R2.fastq

  • Method 2 – Use a range like [0-9], [A-Z], [a-z]:

    ls sample[1-2]*
    sample1_R1.fastq  sample1_R2.fastq  sample2_R1.fastq  sample2_R2.fastq

  • Method 3 – Exclude the unwanted sample ID by prefacing the character class with a ^, which results in inverted behaviour:

    # This is saying: after 'sample', there should be anything EXCEPT a '3':
ls sample[^3]*
    sample1_R1.fastq  sample1_R2.fastq  sample2_R1.fastq  sample2_R2.fastq
Note: [] works on “single-character” ranges only: [0-9] works but [10-13] does not.

These examples may seem trivial, but you can use these techniques to easily operate on selections among 100s or 1000s of files.

3 Brace expansion

Whereas wildcard expansion looks for corresponding files and expands to whichever files are present, brace expansion with {}, is another type of shell expansion and it instead expands to whatever you tell it to.

For example, use .. within {} to indicate ranges of numbers or letters:

  • Create 30 directories, one for each day in September:

4 Renaming files with loops

Sometimes, you need to rename many files in a systematic/repetitive way. This is relatively common with omics data files, as you will often have separate files for each sample, and you may have many dozens of samples.

Manually renaming these one-by-one is tedious as well as extremely error-prone and irreproducible. So, yhis is a good example of a general task that you can apply your coding skills to. For example, maybe you have a few thousand photos you want to rename in a systematic way?

There are many different ways to rename many files in a programmatic way in the shell – admittedly none as easy as one might have hoped. Here, we’ll use the basename command and a for loop. for loops are a verbose method for tasks like renaming, but are relatively intuitive and good to get practice with because you will use them in other contexts throughout the course.

4.1 Creating a set of dummy files to work with

Start with creating some dummy files that represent alignments (the results of aligning reads in FASTQ files to a reference genome, stored in .sam or .bam files):

mkdir -p results/alignments
touch results/alignments/sample{01..50}.sam

Check the names of the files you created and how many there are:

ls results/alignments
results/alignments/sample01.sam
results/alignments/sample02.sam
results/alignments/sample03.sam
results/alignments/sample04.sam
results/alignments/sample05.sam
results/alignments/sample06.sam
# [...output truncated...]
ls results/alignments/ | wc -l
50

Now, say that you noticed these files somehow ended up with the wrong file extension: they are saved as .sam (SAM files) but are really .bam (BAM files). You’ll have to rename them before moving on the next step in your analysis, but it would be tedious, error-prone, and irreproducible to do this by hand. Therefore, let’s use a loop.

4.2 Renaming a single file using variables

To go step-by-step, I will start by showing how you could rename a single file like you would when using a loop, which is using variables. You will also make a separate copy of the files in a separate directory, just to be safe.

To start with, the original file name will be contained in a variable…

oldname=results/alignments/sample01.sam

…and you can also save the new name in a variable:

newname=results/alignments_bam/$(basename "$oldname" .sam).bam

Before actually renaming, note the following trick with echo to just print the command instead of executing it — that can be a really useful way to check what you’re doing is correct when you’re about to run a command you may be nervous about with variables:

# This will not execute the 'mv' command, it just prints it!
# This technique is useful as a sanity check when using variables.
echo mv -v "$oldname" "$newname"
mv -v results/alignments/sample01.sam results/alignments_bam/sample01.bam

Looks good? Then remove echo and rename the file (using the -v option to make mv report what it’s doing):

mv -v "$oldname" "$newname"
results/alignments/sample01.sam -> results/alignments_bam/sample01.bam

4.3 Looping over all files

Here’s how you can loop over these files, saving each file name (one at a time) in the variable $oldname:

for oldname in results/alignments/*.sam; do
    # [renaming code...]
done

Next, inside the loop, assign a new name for each file:

for oldname in results/alignments/*.sam; do
    newname=results/alignments_bam/$(basename "$oldname" .sam).bam
done

Now, build and check the renaming command:

for oldname in *.fastq; do
    newname=results/alignments_bam/$(basename "$oldname" .sam).bam
    echo cp -v "$oldname" "$newname"
done
cp -v results/alignments/sample01.sam results/alignments_bam/sample01.bam
cp -v results/alignments/sample02.sam results/alignments_bam/sample02.bam
cp -v results/alignments/sample03.sam results/alignments_bam/sample03.bam
cp -v results/alignments/sample04.sam results/alignments_bam/sample04.bam
# [...output truncated...]

Finally, actually create the renamed copies by removing echo:

for oldname in *.fastq; do
    newname=results/alignments_bam/$(basename "$oldname" .sam).bam
    cp -v "$oldname" "$newname"
done
‘results/alignments/sample01.sam’ -> ‘results/alignments_bam/sample01.bam’
‘results/alignments/sample02.sam’ -> ‘results/alignments_bam/sample02.bam’
‘results/alignments/sample03.sam’ -> ‘results/alignments_bam/sample03.bam’
‘results/alignments/sample04.sam’ -> ‘results/alignments_bam/sample04.bam’
# [...output truncated...]

  2. Rename files in a batch
    Woops! You stored the alignment files you created in the previous step as SAM files (.sam), but this was a mistake – the files are actually the binary counterparts of SAM files: BAM files (.bam).

    Move into the dir with BAM files, and use a for loop to rename them, changing the extension from .sam to .bam.

    Hints
    • Loop over the files using globbing (wildcard expansion) directly; there is no need to call ls.
    • Use the basename command, or alternatively, cut, to strip the extension.
    • Store the output of the basename (or cut) call using command substitution ($(command) syntax).
    • The new extension can simply be pasted behind the file name, like newname="$filename_no_extension"bam or newname=$(basename ...)bam.

    Solution

     
    for oldname in *.sam; do
    newname=$(basename "$oldname" sam)bam
    mv -v "$oldname" "$newname"
done

    In the code above:

    • $oldname will contain the old file name in each iteration of the loop.
    • We remove the sam suffix using basename "$oldname" sam.
    • We use command substitution ($() syntax) to catch the output of the basename command, and paste bam at the end.

    Also, note that:

    • You don’t need a special construction to paste strings together: you simply type bam after what will be the extension-less file name from the basename command.
    • I used informative variable names (oldname and newname), not cryptic ones like i and o.

    Hints

    Just like you used multiple consecutive brace expansions above, you can use two consecutive wildcard character sets ([]) here.

    Solution

  4. Bonus: a trickier renaming loop
    You now realize that your date format is suboptimal (MM-DD-YYYY; which gave 08-14-2020 and 09-16-2020) and that you should use the YYYY-MM-DD format. Use a for loop to rename the files.

    Hints
    • Use cut to extract the three elements of the date (day, month, and year) on three separate lines.
    • Store the output of these lines in variables using commands substitution, like: day=$(commands).
    • Finally, paste your new file name together like: newname="$part1"_"$year" etc.
    • When first writing your commands, it’s helpful to be able to experiment easily: start by echo-ing a single example file name, as in: echo sample23_C_09-16-2020.sam | cut ....

    Solution
    • In the loop, first use cut to extract the month, day, and year:
      • Start by extracting the entire date: cut by an _ and take the third item (cut -d "_" -f 3).
      • Then extract the different components of the date separately for month, date, and year, with cut -d "-": the first item is the month, the second is the day, and the third is the year.
      • Save these compoinents of the date in variables using command substitution ($()).
    • Second, use cut to extract what we may call the “sample prefix”, which contains the sample number and the treatment.
    • Third, build the new file name simply by putting the variables in the right order with _ and - delimiters.
    • Use mv to rename the files — below, I’ve added -v for verbose so it will report what it does.
    for oldname in *.bam; do
    # Extract and store the month, day, and year:
    # (First cut by '_' taking the 3rd item, then by '-')
    month=$(echo "$oldname" | cut -d "_" -f 3 | cut -d "-" -f 1)
    day=$(echo "$oldname" | cut -d "_" -f 3 | cut -d "-" -f 2)
    year=$(basename "$oldname" .bam | cut -d "_" -f 3 | cut -d "-" -f 3)

    # Extract and store the sample prefix:
    sample_prefix=$(echo "$oldname" | cut -d "_" -f 1-2)

    # Paste together the new name:
    newname="$sample_prefix"_"$year"-"$month"-"$day".bam

    # Execute the move:
    mv -v "$oldname" "$newname"
done
    ‘sample01_A_08-14-2020.bam’ -> ‘sample01_A_2020-08-14.bam’
‘sample01_A_09-16-2020.bam’ -> ‘sample01_A_2020-09-16.bam’
‘sample01_B_08-14-2020.bam’ -> ‘sample01_B_2020-08-14.bam’
‘sample01_B_09-16-2020.bam’ -> ‘sample01_B_2020-09-16.bam’
‘sample01_C_08-14-2020.bam’ -> ‘sample01_C_2020-08-14.bam’

5 The find command to find files

5.1 Two problems you may run into

Consider the following examples from Buffalo (2015) of problems you may run into. Say that you try to pipe ls output into the imaginary program process_fastq, which can operate on multiple FASTQ files at once, taking each as an argument:

ls *.fastq | process_fastq

Any spaces in the listed file names would lead to trouble here, since those file names would be erroneously split into separate arguments. A solution would be to use direct globbing:

process_fastq *.fastq

However, a different problem could occur here: if the number of globbed files is very high, you may get an error that the “argument list is too long”.

The find and xargs commands can deal with both of these problems. More generally, these commands are useful for:

  • find: file searching and processing beyond ls’s capabilities
  • xargs: multi-file and parallel processing without loops.

Let’s create some files to try these commands:

mkdir -p zmays-snps/{data/seqs,scripts,analysis}
touch zmays-snps/data/seqs/zmays{A,B,C}_R{1,2}.fastq

5.2 find basics

The basic syntax for find is:

find [path] [expression-1] [expression-2] ...

find will print all files by default, like ls – but unlike ls, it is recursive by default:

find zmays-snps
zmays-snps/
zmays-snps/data
zmays-snps/data/seqs
zmays-snps/data/seqs/zmaysC_R1.fastq
zmays-snps/data/seqs/zmaysA_R1.fastq
zmays-snps/data/seqs/zmaysB_R1.fastq
zmays-snps/data/seqs/zmaysB_R2.fastq
zmays-snps/data/seqs/zmaysC_R2.fastq
zmays-snps/data/seqs/zmaysA_R2.fastq
zmays-snps/scripts
zmays-snps/analysis

Compare this with the corresponding ls output:

ls zmays-snps
analysis  data  scripts

Using the -name option, you can also glob like with ls:

cd zmays-snps
find data/seqs -name "zmaysB*fastq"
data/seqs/zmaysB_R1.fastq
data/seqs/zmaysB_R2.fastq

5.3 find functionality beyond that of ls

First, you can use -type as an expression to limit results by file type:

# "-type f" to only match regular files (not, e.g., dirs)
find data/seqs -name "zmaysB*fastq" -type f

In the previous command, the two expressions were implicitly connected with a logical and: the resulting matches had to be regular files and also had to have _zmaysB*fastq_ in the name. You can connect expressions explicitly using the -and operator…

find data/seqs -name "zmaysB*fastq" -and -type f 
TBA

…or the -or operator:

find data/seqs -name "zmaysA*fastq" -or -name "zmaysC*fastq" 
TBA

You can negate expressions with ! — though you must quote the ! so it doesn’t get evaluated by the shell:

# Find regular fies that do NOT match "zmaysC*fastq"
find data/seqs -type f "!" -name "zmaysC*fastq"

touch data/seqs/zmays{A,C}_R{1,2}-temp.fastq

5.5 Running commands on find’s results

Now, say that you instead want to remove the temporary files we saw above. We can do this using -exec followed by the rm command (in this case, using rm -i for interactive removal):

find data/seqs -name "*-temp.fastq" -exec rm -i {} \;

Here, {} is the placeholder for the file names we are passing on, and you have to indicate the end of our command with an escaped semicolon: \;.

-exec can be very useful to process file queries that are more complicated than what a simple globbing pattern allows for. With -exec, you can use any command to operate on the files that you found.

Finally, note that for the common operation of deleting files, a shortcut exists:

find zmays-snps/data/seqs -name "*-temp.fastq" -delete

6 The xargs command to repeat commands without loops

xargs is to be read/pronounced as x-args, where “args” means “arguments”.

This command passes arguments, supplied via standard in, on to another command. For example…

find data/seqs -name "*-temp.fastq" | xargs rm

…is equivalent to the following, where rm receives the very same list of files as its arguments:

rm data/seqs/*-temp.fastq

However, with xargs, you can bypass the problem of a maximum number of arguments to rm. Specifically, you can easily pass one argument at a time with -n 1:

find data/seqs -name "*-temp.fastq" | xargs -n 1 rm

This command runs rm as many times as there are *-temp.fastq files.

6.1 xargs versus find -exec

By using xargs instead of find -exec, you separate the process that finds the files you want to operate on, from the actual operations.

This can be beneficial, such as when you want to carefully inspect a list of files doing anything — for example:

  • Create some dummy files to practice on:

    touch data/seqs/zmays{A,C}_R{1,2}-temp.fastq

  • Save the find results in a text file:

    find data/seqs -name "*-temp.fastq" > files-to-delete.txt
cat files-to-delete.txt
    data/seqs/zmaysC_R1-temp.fastq
data/seqs/zmaysA_R1-temp.fastq
data/seqs/zmaysA_R2-temp.fastq
data/seqs/zmaysC_R2-temp.fastq

  • Now pass that list of files to rm:

    cat files-to-delete.txt | xargs rm

6.2 find => xargs and spaces in file names

As always, spaces in file names can trip you up – but you were promised a solution with find and xargs!

However, out of the box, the below does in fact fail:

touch "samples A.txt"  "samples B.txt" 
  
find . -name "samples [AB].txt" | xargs rm
rm: cannot remove './samples': No such file or directory
rm: cannot remove 'A.txt': No such file or directory
rm: cannot remove './samples': No such file or directory
rm: cannot remove 'B.txt': No such file or directory

The solution is to use -print0 with find, so it prints files with a “null byte” as the delimiter. Then, you also need to tell xargs about this, using -0:

find . -name "samples [AB].txt" -print0 | xargs -0 rm -v
removed './samples A.txt'
removed './samples B.txt'
xargs as an alternative to loops

With xargs, you can also specify where you want to insert the arguments that are being passed on:

find data/seqs -name "*.fastq" |
    xargs basename -s ".fastq" |
    xargs -I{} fastq_stat --in {}.fastq --out results/{}.txt

Above, -I{} specified that the arguments were passed on with the placeholder {}. We were then also able to use {} multiple times. The above code does something that you may be otherwise be inclined to do in a loop — the above is equivalent to:

for fastq_file in data/seqs/*fastq; do
    id=$(basename "$fastq_file" .fastq)
    fastq_stat --in "$fastq_file" --out results/"$id".txt
done

One advantage of using xargs instead of a for loop is that you have control over parallelization.

  • To parallelize, i.e. to spawn multiple simultaneous process, you can send each process to the background in the for loop using &:

    for fastq_file in *fastq; do
    fastq_short=$(basename $fastq_file .fastq) 
    fastq_stat --in $fastq_file --out results/$fastq_short.txt &
done

    However, this would spawn exactly as many processes as there are input files, which could be way more than what we want.

  • With xargs, you can control the number of simultaneous processes that are spawned using -P (here set to 6):

    find data/seqs -name "*.fastq" |
    xargs basename -s ".fastq" |
    xargs -P 6 -I{} fastq_stat --in {}.fastq --out results/{}.txt

If you like the xargs approach to running multiple processes, you may also be interested in the parallel command, which is even more powerful than xargs. I personally don’t do this very much because I tend to submit separate batch jobs for each file, which can easily be done with simple for loops.

Your bash shell is configured using hidden text files in your $HOME dir:

Some settings that are / can be stored in these config files:

  • The look of your prompt.

  • The $PATH, a list of directories with binaries (software executables) that the computer is aware of.

Tip

To not have to deal with the login/non-login shell distinction, it is common to put all settings in one of these files (often .bashrc) and let the second file (often .bash_profile) run the first file whenever it itself is being run.

8 $PATH: A list of directories with binaries

$PATH is another environment variable like $HOME and $USER.

It lists the directories that will be searched when you type a program’s name. This allows you to run programs without specifying the full path to the executable. For example:

vcftools
#> VCFtools (0.1.16)
#> (c) Adam Auton and Anthony Marcketta 2009
  
# To check where the program's binary is located:
which vcftools
#> /usr/bin/vcftools

To check which directories are in your $PATH, you can simply echo it:

echo $PATH
/apps/xalt/xalt/bin:/opt/mvapich2/intel/19.0/2.3.3/bin:/apps/gnu/8.4.0/bin:/opt/intel/19.0.5/itac_latest/bin:/opt/intel/19.0.5/advisor/bin64:/opt/intel/19.0.5/vtune_amplifier/bin64:/opt/intel/19.0.5/inspector_2019/bin64:/opt/intel/19.0.5/compilers_and_libraries_2019/linux/bin/intel64:/apps/software_usage:/usr/lib64/qt-3.3/bin:/opt/osc/bin:/opt/moab/bin:/usr/local/bin:/usr/bin:/usr/local/sbin:/usr/sbin:/opt/ibutils/bin:/opt/ddn/ime/bin:/opt/puppetlabs/bin:/users/PAS0471/jelmer/software/bin

That output looks strange and is hard to read, because the directories are separated by colons :. Let’s make that a bit more readable:

echo $PATH | tr ":" "\n" | nl
1  /apps/xalt/xalt/bin
2  /opt/mvapich2/intel/19.0/2.3.3/bin
3  /apps/gnu/8.4.0/bin
4  /opt/intel/19.0.5/itac_latest/bin
5  /opt/intel/19.0.5/advisor/bin64
[...output-truncated...]

You can easily modify your $PATH. To add a directory to your $PATH in the current session, you simply append a new dir after a colon:

PATH=$PATH:~/new-dir-with-software/

However, this change will not have any effects outside of your current bash sessions.

For lasting changes, you should edit your bash configuration files (like ~/.bashrc), from which $PATH is loaded whenever you open a terminal:

echo "PATH=$PATH:~/new-dir-with-software/" >> ~/.bashrc
