2.1 Create a dummy project folder structure

First, we’ll create a set of directories representing a dummy research project:

# (You should be in /fs/ess/PAS2880/users/$USER/week03/sandbox)
mkdir dummy-project
cd dummy-project
# The -p option for mkdir will allow for 'recursive' (nested) dir creation
mkdir -p data/fastq scripts results/figures results/alignments

We will use the touch command to create empty files that are mock representations of FASTQ sequence files with forward (“R1”) and reverse (“R2”) DNA sequence reads for 3 samples:

# (Copy-and-paste this rather than typing it out)

touch data/fastq/sample2_R1.fastq data/fastq/sample2_R2.fastq

2.2 All shell wildcards

There are two more shell wildcards — here is a complete overview of shell wildcards:

Wildcard Matches
* Any number of any character, including nothing
? Any single character
[] and [^] One or none (^) of the “character set” within the brackets

Using the more restrictive wildcard ? can be useful to prevent accidental matches. Here is an example of using the ? wildcard to match both R1 and R2:

ls sample1_R?.fastq
sample1_R1.fastq  sample1_R2.fastq

The character class wildcard [] can be useful when wanting to include or exclude multiple files among files with rather similar names. For example, to match files for sample1 and sample2 using only a character class with []:

  • Method 1 — List all possible characters (1 and 2 in this case):

    ls sample[12]*
    sample1_R1.fastq  sample1_R2.fastq  sample2_R1.fastq  sample2_R2.fastq

  • Method 2 – Use a range like [0-9], [A-Z], [a-z]:

    ls sample[1-2]*
    sample1_R1.fastq  sample1_R2.fastq  sample2_R1.fastq  sample2_R2.fastq

  • Method 3 – Exclude the unwanted sample ID:

    ls sample[^3]*
    sample1_R1.fastq  sample1_R2.fastq  sample2_R1.fastq  sample2_R2.fastq
Note: [] works on single character ranges only: 0-9 works but 10-13 does not.

The examples so far may seem trivial, but you can use these techniques to easily operate on selections among 100s or 1000s of files.


3 Brace expansion

Whereas wildcard expansion looks for corresponding files and expands to whichever files are present, brace expansion with {}, is another type of shell expansion that expands to whatever you tell it to.

# First move up to zmays-snps
cd ../..

Use .. within {} to indicate ranges of numbers or letters:

# Here we'll create 31 _dirs_ for different dates
mkdir -p data/obs/2025-09-{01..31}

ls data/obs
2025-09-01  2025-09-04  2025-09-07  2025-09-10  2025-09-13  2025-09-16  2025-09-19  2025-09-22  2025-09-25  2025-09-28  2025-09-31

# Here we'll create 6 empty _files_
touch results/figures/fig-1{A..F}.png

ls results/figures
fig-1A.png  fig-1B.png  fig-1C.png  fig-1D.png  fig-1E.png  fig-1F.png

Finally, you can also use a comma-separated list, and multiple brace expansions — with the latter, you will get all combinations among values in the expansions:

mkdir -p data/obs2/treatment-{Kr,Df,Tr}_temp-{lo,med,hi}

ls data/obs2
treatment-Df_temp-hi   treatment-Kr_temp-hi   treatment-Tr_temp-hi
treatment-Df_temp-lo   treatment-Kr_temp-lo   treatment-Tr_temp-lo
treatment-Df_temp-med  treatment-Kr_temp-med  treatment-Tr_temp-med

4 Bash configuration files

Your bash shell is configured using hidden text files in your $HOME dir:

  • ~/.bashrc – for non-login shells
  • ~/.bash_profile – for non-login shells FIX

These can be viewed and edited like normal text files:

cat ~/.bashrc    # Or open in VS Code

Some settings that are / can be stored in these config files:

  • The look of your prompt.
  • aliases – personal, custom shortcuts for (complex) commands.
  • The $PATH, a list of directories with binaries (software executables) that the computer is aware of.
  • Other custom settings like running setup scripts.
Tip

To not have to deal with the login/non-login shell distinction, it is common to put all settings in one of these files (often .bashrc) and let the second file (often .bash_profile) run the first file whenever it itself is being run.

5 $PATH: A list of directories with binaries

$PATH is another environment variable like $HOME and $USER.

It lists the directories that will be searched when you type a program’s name. This allows you to run programs without specifying the full path to the executable. For example:

vcftools
#> VCFtools (0.1.16)
#> (c) Adam Auton and Anthony Marcketta 2009
  
# To check where the program's binary is located:
which vcftools
#> /usr/bin/vcftools

To check which directories are in your $PATH, you can simply echo it:

echo $PATH
/apps/xalt/xalt/bin:/opt/mvapich2/intel/19.0/2.3.3/bin:/apps/gnu/8.4.0/bin:/opt/intel/19.0.5/itac_latest/bin:/opt/intel/19.0.5/advisor/bin64:/opt/intel/19.0.5/vtune_amplifier/bin64:/opt/intel/19.0.5/inspector_2019/bin64:/opt/intel/19.0.5/compilers_and_libraries_2019/linux/bin/intel64:/apps/software_usage:/usr/lib64/qt-3.3/bin:/opt/osc/bin:/opt/moab/bin:/usr/local/bin:/usr/bin:/usr/local/sbin:/usr/sbin:/opt/ibutils/bin:/opt/ddn/ime/bin:/opt/puppetlabs/bin:/users/PAS0471/jelmer/software/bin

That output looks strange and is hard to read, because the directories are separated by colons :. Let’s make that a bit more readable:

echo $PATH | tr ":" "\n" | nl
1  /apps/xalt/xalt/bin
2  /opt/mvapich2/intel/19.0/2.3.3/bin
3  /apps/gnu/8.4.0/bin
4  /opt/intel/19.0.5/itac_latest/bin
5  /opt/intel/19.0.5/advisor/bin64
[...output-truncated...]

You can easily modify your $PATH. To add a directory to your $PATH in the current session, you simply append a new dir after a colon:

PATH=$PATH:~/new-dir-with-software/

However, this change will not have any effects outside of your current bash sessions.

For lasting changes, you should edit your bash configuration files (like ~/.bashrc), from which $PATH is loaded whenever you open a terminal:

echo "PATH=$PATH:~/new-dir-with-software/" >> ~/.bashrc
