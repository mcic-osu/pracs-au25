2 Wildcard expansion

Shell wildcard expansion is a very useful technique to select files, where wildcards are characters that have a special meaning. With the following files in our directory…

cd data/fastq
ls
sample1_R1.fastq  sample1_R2.fastq  sample2_R1.fastq
sample2_R2.fastq  sample3_R1.fastq  sample3_R2.fastq

…let’s say we wanted to operate only on a subset of these files. The first examples will continue to use ls, but we can use this technique with any command that operates on files.

2.1 The * wildcard

By far the most commonly used wildcard is *, which matches any number of any combination of characters (including “nothing” – the absence of any characters). For example, we can match only the two sample1 files with a * using:

# This matches files that start with "sample1"
ls sample1*
sample1_R1.fastq  sample1_R2.fastq

If the pattern we use for matching is in the middle of the filename, we need a * on both sides of it — for example:

# This matches files that contain, anywhere in their names, "R1":
ls *R1*
sample1_R1.fastq  sample2_R1.fastq  sample3_R1.fastq

Selecting files with wildcard expansion is called globbing. When globbing, the pattern has to match the entire file name (i.e. no partial matches like with grep), so the following doesn’t match anything, in this scenario:

# This matches files that _end in_ R1, but there are no such files:
ls *R1
ls: cannot access *R1: No such file or directory

In summary:

Pattern Matches files whose names…
sample1* Start with “sample1”
*fastq End with “.fastq”
*_R1* Contain “_R1”
* (matches all files in the working dir)1

There are a couple more shell wildcards, but these are much more rarely used: check the bonus reading at the bottom of the page if you’re curious.

Expansion is done by the shell itself

It is important to realize that the “expansion” –of a wildcard to matching file names– is done by the shell and not by ls or another command you might be using wildcards with. This means that a command like ls will “see”/“receive” the list of files after the expansion has already happened.

So, when you type…

ls sample1*fastq

…the shell will first do wildcard expansion and will therefore end up running, in this particular case:

ls sample1_R1.fastq sample1_R1.fastq

This also means that wildcard expansion works with any command that accepts multiple paths as arguments, such as copy (cp command), move (mv) or delete (rm). For example, we can remove any stray .txt files in our dir for FASTQ files using:

# (The -v option will make rm report what it's removing)
rm -v *txt
removed ‘sample1.txt’
removed ‘sample2.txt’
In case you have heard of “regular expressions”: these are not the same as wildcards (Click to expand)

Don’t confuse wildcards with regular expressions! You may have used regular expressions before, for example with R or a text editor. They are similar to but not the same as shell wildcards.


3 Variables and command substitution

Now, we’ll cover a few topics that do not directly relate to files, but that you need to know about before the application at the end of this session: renaming files with a loop. Additionally, you will keep using these constructs throughout the course.

3.1 Variables

Variables are truly ubiquitous in programming. We typically use them for items that:

  • We refer to repeatedly and/or
  • Are subject to change.

These tend to be settings like the paths to input and output files, and parameter values for programs. Using variables makes it easier to change such settings and makes it possible to write scripts and programs that are flexible depending on user input. Earlier, we already saw a couple of handy applications of variables: for example, the environment variable $USER contains our user name.

Assigning and referencing variables

To assign a value to a variable in the shell, use the syntax variable_name=value:

# Assign the value "beach" to a variable with the name "location":
location=beach

# Assign the value "200" to a variable with the name "nr_samples":
nr_samples=200
Recall that there can’t be spaces around the equals sign (=)!

To reference a variable (i.e., to access its value):

  • You need to put a dollar sign $ in front of its name.
  • It is good practice to double-quote ("...") variable names2.

As before with the environment variables $USER and $HOME, we’ll use the echo command to see what values our variables contain:

echo "$location"
beach
echo "$nr_samples"
200

Conveniently, we can use variables in lots of contexts, as if we had directly typed their values:

input_file=data/fastq/sample1_R1.fastq

ls -lh "$input_file"
-rw-rw----+ 1 jelmer PAS0471 0 Mar  7 13:17 data/fastq/sample1_R1.fastq

You will learn more about variables and their usage when we cover shell scripts in a few weeks.

3.2 Command substitution

Command substitution allows you to store the output of a command in a variable.

Let’s see an example. As you know, the date command will print the current date and time:

date
Thu Mar  7 14:52:22 EST 2024

If we try to store the date in a variable directly, it doesn’t work: the literal string “date” is stored instead:

today=date
echo "$today"
date

That’s why we need command substitution, which we can use by wrapping the command inside $():

today=$(date)
echo "$today"
Thu Mar  7 14:53:11 EST 2024

One practical example of using command substitution is when you want to automatically include the current date in a file name (with “automatic” meaning that you can use the same command regardless of the date, and that you could use it in a script that you could run at any point). First, note that we can use date +%F to print the date in YYYY-MM-DD format, and omit the time:

date +%F
2024-03-07

Let’s use that in a command substitution:

today=$(date +%F)
touch README_"$today".txt

ls
README_2024-03-07.txt
Or insert the command substitution on the fly

It is even possible to do this all in one go, by using the command substitution $(date +%F) directly in our touch command, rather than first assigning it to a variable:

touch README_"$(date +%F)".txt

Exercise: Command substitution

Say we wanted to count and report the number of FASTQ files in a directory in a generalized, programmatic way. To do the counting, we can run:

4 For loops

Loops are another universal element of programming languages, and are used to repeat operations. Here, we’ll only cover the most common type of loop: the for loop.

A for loop iterates over a collection, such as a list of files, and allows you to perform one or more actions for each element in the collection. In the example below, our “collection” is just a short list of numbers (1, 2, and 3):

for a_number in 1 2 3; do
    echo "In this iteration of the loop, the number is $a_number"
    echo "--------"
done
In this iteration of the loop, the number is 1
--------
In this iteration of the loop, the number is 2
--------
In this iteration of the loop, the number is 3
--------

The indented lines between do and done contain the code that is being executed as many times as there are items in the collection: in this case 3 times, as you can tell from the output above.

What was actually run under the hood is the following:

# (Don't run this)
a_number=1
echo "In this iteration of the loop, the number is $a_number"
echo "--------"

a_number=2
echo "In this iteration of the loop, the number is $a_number"
echo "--------"

a_number=3
echo "In this iteration of the loop, the number is $a_number"
echo "--------"

Here are two key things to understand about for loops:

  • In each iteration of the loop, one element in the collection is being assigned to the variable specified after for. In the example above, we used a_number as the variable name, so that variable contained 1 when the loop ran for the first time, 2 when it ran for the second time, and 3 when it ran for the third and last time.

  • The loop runs sequentially for each item in the collection, and will run exactly as many times as there are items in the collection.

A further explanation of for loop syntax

On the first and last, unindented lines, for loops contain the following mandatory keywords:

Keyword Purpose
for After for, we set the variable name (an arbitrary name; above we used a_number)
in After in, we specify the collection (list of items) we are looping over
do After do, we have one ore more lines specifying what to do with each item
done Tells the shell we are done with the loop

Combining loops and globbing

A very useful strategy is to loop over files with globbing, for example:

for fastq_file in *fastq; do
    echo "Running an analysis for file $fastq_file"...
    # [This is where you would put additional commands to process each FASTQ file]
done
Running an analysis for file sample1_R1.fastq...
Running an analysis for file sample1_R2.fastq...
Running an analysis for file sample2_R1.fastq...
Running an analysis for file sample2_R2.fastq...
Running an analysis for file sample3_R1.fastq...
Running an analysis for file sample3_R2.fastq...

5 The basename command

In loops and other contexts where you are working with file names programmatically, you often have a path to a file and need to extract just the file name part from it.

For example, we can think of the path data/fastq/sample1_R1.fastq as consisting of a directory part (data/fastq/) and a filename part (sample1_R1.fastq).

The basename command will extract just the filename part:

basename data/fastq/sample1_R1.fastq
sample1_R1.fastq

Optionally, it can remove a suffix too, most typically the file extension:

basename data/fastq/sample1_R1.fastq .fastq
sample1_R1


6 Renaming files with loops

Sometimes, you need to rename many files in a systematic/repetitive way. This is relatively common with omics data files, as you will often have separate files for each sample, and you may have many dozens of samples.

Manually renaming these one-by-one is tedious as well as extremely error-prone and not-reproducible, while doing this with code is a good example of a general task that you can apply your coding skills to. For example, maybe you have a few thousand photos that you want to rename in a systematic way?

There are many different ways to rename many files in a programmatic way in the shell – admittedly none as easy as one might have hoped. Here, we’ll use the basename command and a for loop. for loops are a verbose method for tasks like renaming, but are relatively intuitive and good to get practice with because you will use them in other contexts throughout the course.

Creating a set of dummy files to work with

We will start with creating some dummy files that represent alignments (the results of aligning reads in FASTQ files to a reference genome). These are stored in .sam or .bam files.

To create many files at once, we will use a trick called “brace expansion” (because this is not a commonly used technique, I will only explain it in the optional bonus reading at the bottom of the page):

cd /fs/ess/PAS2880/users/$USER/week03
touch results/alignments/sample{01..50}.sam

Let’s check the names of the files we created and how many there are:

ls results/alignments
results/alignments/sample01.sam
results/alignments/sample02.sam
results/alignments/sample03.sam
results/alignments/sample04.sam
results/alignments/sample05.sam
results/alignments/sample06.sam
# [...output truncated...]
ls results/alignments/ | wc -l
50

Now, let’s say that we noticed these files somehow have the wrong extension: they are saved as .sam (SAM files) but are really .bam (BAM files). We’ll have to rename them before moving on the next step in our analysis, but it would be tedious (and error-prone! and not-reproducible!) to do this by hand. We will therefore use a loop.

Renaming a single file using variables

To go step-by-step, I will start by showing how we could rename a single file in the way that we would have to do this in a loop — using variables.

We will actually make a separate copy of the files in a separate directory, just to be safe.

To start with, the original file name will be contained in a variable…

oldname=results/alignments/sample01.sam

…and we can also save the new name in a variable:

newname=results/alignments_bam/$(basename "$oldname" .sam).bam

Before actually renaming, note the following trick with echo to just print the command instead of executing it — that can be a really useful way to check what you’re doing is correct when you’re about to run a command you may be nervous about with variables:

echo mv -v "$oldname" "$newname"
mv -v results/alignments/sample01.sam results/alignments_bam/sample01.bam

Looks good? Then we remove echo and rename the file (we’re using the -v to make mv report what it’s doing):

mv -v "$oldname" "$newname"
results/alignments/sample01.sam -> results/alignments_bam/sample01.bam

Looping over all files

Here’s how we can loop over these files, saving each file name (one at a time) in the variable $oldname:

for oldname in results/alignments/*.sam; do
    # ...
done

Next, we assign a new name for each file:

for oldname in results/alignments/*.sam; do
    newname=results/alignments_bam/$(basename "$oldname" .sam).bam
done

We build and check the renaming command:

for oldname in *.fastq; do
    newname=results/alignments_bam/$(basename "$oldname" .sam).bam
    echo cp -v "$oldname" "$newname"
done
cp -v results/alignments/sample01.sam results/alignments_bam/sample01.bam
cp -v results/alignments/sample02.sam results/alignments_bam/sample02.bam
cp -v results/alignments/sample03.sam results/alignments_bam/sample03.bam
cp -v results/alignments/sample04.sam results/alignments_bam/sample04.bam
# [...output truncated...]

Finally, we actually copy and rename by removing echo:

for oldname in *.fastq; do
    newname=results/alignments_bam/$(basename "$oldname" .sam).bam
    cp -v "$oldname" "$newname"
done
‘results/alignments/sample01.sam’ -> ‘results/alignments_bam/sample01.bam’
‘results/alignments/sample02.sam’ -> ‘results/alignments_bam/sample02.bam’
‘results/alignments/sample03.sam’ -> ‘results/alignments_bam/sample03.bam’
‘results/alignments/sample04.sam’ -> ‘results/alignments_bam/sample04.bam’

7 Optional bonus reading

7.1 Other shell wildcards

There are two more shell wildcards — here is a complete overview of shell wildcards:

Wildcard Matches
* Any number of any character, including nothing
? Any single character
[] and [^] One or none (^) of the “character set” within the brackets

Using the more restrictive wildcard ? can be useful to prevent accidental matches. Here is an example of using the ? wildcard to match both R1 and R2:

ls sample1_R?.fastq
sample1_R1.fastq  sample1_R2.fastq

The character class wildcard [] can be useful when wanting to include or exclude multiple files among files with rather similar names. For example, to match files for sample1 and sample2 using only a character class with []:

  • Method 1 — List all possible characters (1 and 2 in this case):

    ls sample[12]*
    sample1_R1.fastq  sample1_R2.fastq  sample2_R1.fastq  sample2_R2.fastq

  • Method 2 – Use a range like [0-9], [A-Z], [a-z]:

    ls sample[1-2]*
    sample1_R1.fastq  sample1_R2.fastq  sample2_R1.fastq  sample2_R2.fastq

  • Method 3 – Exclude the unwanted sample ID:

    ls sample[^3]*
    sample1_R1.fastq  sample1_R2.fastq  sample2_R1.fastq  sample2_R2.fastq
Note: [] works on single character ranges only: 0-9 works but 10-13 does not.

The examples so far may seem trivial, but you can use these techniques to easily operate on selections among 100s or 1000s of files.

7.2 Brace expansion

Whereas wildcard expansion looks for corresponding files and expands to whichever files are present, brace expansion with {}, is another type of shell expansion that expands to whatever you tell it to.

# First move up to zmays-snps
cd ../..

Use .. within {} to indicate ranges of numbers or letters:

# Here we'll create 31 _dirs_ for different dates
mkdir -p data/obs/2024-03-{01..31}

ls data/obs
2024-03-01  2024-03-04  2024-03-07  2024-03-10  2024-03-13  2024-03-16  2024-03-19  2024-03-22  2024-03-25  2024-03-28  2024-03-31
2024-03-02  2024-03-05  2024-03-08  2024-03-11  2024-03-14  2024-03-17  2024-03-20  2024-03-23  2024-03-26  2024-03-29
2024-03-03  2024-03-06  2024-03-09  2024-03-12  2024-03-15  2024-03-18  2024-03-21  2024-03-24  2024-03-27  2024-03-30
# Here we'll create 6 empty _files_
touch results/figures/fig-1{A..F}.png

ls results/figures
fig-1A.png  fig-1B.png  fig-1C.png  fig-1D.png  fig-1E.png  fig-1F.png

Finally, you can also use a comma-separated list, and multiple brace expansions — with the latter, you will get all combinations among values in the expansions:

mkdir -p data/obs2/treatment-{Kr,Df,Tr}_temp-{lo,med,hi}
