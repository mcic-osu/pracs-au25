Exercise 2: Exploring the GTF annotation file

  1. Navigate into the dir garrigos-data/sandbox you should have created in this week’s second session.1

  2. Copy the genome annotation file garrigos-data/ref/GCF_016801865.2.gtf.gz to a file called annot.gtf.gz inside your sandbox working dir. While doing so, make the cp command report what it’s doing (“verbose”).

  3. Check the size of the annot.gtf.gz file. Then, unzip (decompress) the GTF file with the gunzip command as shown below. Finally, check the size of the resulting annot.gtf file: how large is the size difference between the compressed and uncompressed file?

    gunzip annot.gtf.gz

  4. How many lines does the GTF file contain?

  5. The first several lines of the GTF file are not part of its main table. In the main table, each line represents a “genomic feature” (gene, exon, etc.) for which information is presented across the columns.

    • Combine grep -v2, a pipe, and wc -l to count the number of line in the main table. Take a peek at the file first, so you can decide on a search pattern for grep.
    • Comparing the linecount from this and the previous exercise, does the difference reflect the number of header lines?
    • If not, can you figure out which other line(s) contain the pattern you used with grep above? (Review the “Additional grep tips” box in the section on grep to find an option that might help you make sense of that.)

  6. The first column of the GTF table has the name of the “sequence” (chromosome, scaffold, or contig) from the corresponding genome assembly FASTA file that the feature in question is located on. How many distinct such sequences are represented in the annotation?

  7. Store a list of distinct sequences in the GTF (see the previous exercise) in a file scaffolds.txt.

  8. The seventh column of the GTF table indicates which strand (+ or -) the feature is on3. How many features are on the + strand and how many are on the - strand? (The easiest way to answer this is to produce a “count table” like we this towards the end of this section.)

  9. The third column of the GTF table has the feature type (e.g. “gene” or “exon”). How many genes does the annotation contain?

    Click here for a hint

    You want to count the number of lines where the third column is gene. However, just greping for "gene" would also turn up other lines that contain this string, and not result in a correct count. Therefore, the easiest solution is to create a count table of this column, and look for the gene count in the resulting table.

  10. Each gene can have any number of exons and other features, and you may wonder how may (e.g.) exons a gene of interest has. The GTF files has a hierarchical structure to it such that each exon entry has a reference to the gene that it is a part of in the final column. For gene XXX - TBA, create a count table of its features.

  11. Produce a 3-column table with the scaffold, start position, and end position of each start codon. Store that table in a file start_codons.tsv. (You can safely assume that start_codon only occurs in the third column and that all lines with that string therefore contain start codon features.)

  12. Count the number of small nuclear RNAs (snRNA) in the annotation. You’ll want a “gene”-level count, and because the word “snRNA” also occurs for other features, you should use the output of an initial grep search to figure out what your final search pattern will be.

  13. Bonus: Which sequence (scaffold) appears to be the largest one?

    Click here for a hint

    This information is not directly contained in the GTF file, but if you find the single highest number in the (start or) end coordinate column, and check which sequence that is on, you will most likely get the correct answer.

    To do this, you need to first cut the relevant columns and then sort specifically by the coordinate column (using the -k option).

Exercise 3: Exploring the FASTQ files

  1. Navigate into the dir with FASTQ files from the Garrigos et al. data.

  2. How many reads does the file ERR10802863_R1.fastq.gz contain?

  3. Bonus: How many reads are in all R1 files combined?

  • Using the read length information in the FASTQ header, create a count table of read lengths.

zcat ERR10802863_R1.fastq.gz | grep @ | cut -d= -f2 | sort | uniq -c

  • Under the assumption that stretches of N’s do not occur in the sequence quality lines (which they don’t, in this case), count the number sequences that have at least 10 consecutive Ns.

  • Compare this number with the number of 35-bp reads. What does this tell you? With grep -A1, you can print the line after each match. Can you check what the 35-bp reads look like?

  • How many reads contain the sequence ACGT? (Again under the assumption that this does not occure in the sequence quality line.)

\1. Navigate into the dir garrigos-data/sandbox 
# (You should already be in /fs/ess/PAS2880/users/$USER/)
cd garrigos-data/sandbox

If you needed to also create the sandbox dir:

# (You should already be in /fs/ess/PAS2880/users/$USER/)
mkdir garrigos-data/sandbox
cd garrigos-data/sandbox
\2. Copy the genome annotation file garrigos-data/ref/GCF_016801865.2.gtf.gz

We use the -v option to make copy report what it’s doing:

cp -v ../ref/GCF_016801865.2.gtf.gz annot.gtf.gz
'../ref/GCF_016801865.2.gtf.gz' -> 'annot.gtf.gz'
\3. Unzip (decompress) the GTF file

  • Check the file size:

    ls -lh
    -rw-rw----+ 1 jelmer PAS0471 5.1M Jul 14 18:55 annot.gtf.gz

  • Unzip:

    gunzip annot.gtf.gz

  • Check the file size (and name) again:

    ls -lh
    -rw-rw----+ 1 jelmer PAS0471 123M Jul 14 18:55 annot.gtf

  • That’s a pretty big difference, from 5.1 Mb to 123 Mb! The amount of space saved by file compression varies a lot and depends on the amount of repetition in the uncompressed file. GTF files are highly repetitive, so relatively much space can be saved.

\4. How many lines does the GTF file contain?

A simple line count tells you that the file has 408,402 lines:

wc -l annot.gtf 
408402 annot.gtf
\5. Count the number of line in the GTF table.

  • Since the header lines contain a #, we will want to exclude those and then count the resulting number of lines:

    grep -v "#" annot.gtf | wc -l
    TBA

  • The file has only 3 header lines, while the line count has decreased by 4. Which other line has a #?

    grep -n "#" annot.gtf
    TBA

    Looks like the last line is ##!

\6. How many distinct sequences (scaffolds etc.) are represented in the annotation? 
grep -v "#" annot.gtf | cut -f 1 | sort | uniq | wc -l
TBA
\7. Store the list of distinct sequences in the GTF in a file scaffolds.txt. 
grep -v "#" annot.gtf | cut -f 1 | sort > scaffolds.txt
\8. How many features are on the + strand and how many are on the - strand? 
grep -v "#" annot.gtf | cut -f 7 | sort | uniq -c
TBA
\9. How many genes does the annotation contain? 
grep -v "#" annot.gtf | cut -f 3 | sort | uniq -c
TBA

You could also grep this list for gene:

grep -v "#" annot.gtf | cut -f 3 | sort | uniq -c | grep "gene"
TBA
\10. Create a count table of features for gene XXX 
grep "XXX" annot.gtf | cut -f3 | sort | uniq -c
\11. Create a start codon coordinate table 
grep -v "#" annot.gtf | cut -f 1,4,5 > start_codons.tsv
\12. Count the number of snRNAs in the annotation.

Because the search pattern itself contains double quotes ("), the easiest way out is to use single quotes (') around it:

grep -c 'gene_biotype "snRNA"' annot.gtf
\13. Which sequence (scaffold) appears to be the largest one? 
grep -v "#" annot.gtf | cut -f 1,5 | sort -k2nr | head
