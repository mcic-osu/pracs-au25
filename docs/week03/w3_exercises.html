GTF file info

As mentioned in this week’s first lecture, the main part of a GTF file is a table with:

  • One row for each annotated “genomic feature” (gene, exon, intron, etc.)
  • Columns with information like the genomic coordinates of the features

However, the file typically starts with header lines that contain metadata and start with #. In some cases, the header can have hundreds of lines, including a list of each represented sequence (chromosome/scaffold/contig). “Our” GTF file only has a few header lines, though:

zcat ../ref/GCF_016801865.2.gtf.gz | head -n 5
#gtf-version 2.2
#!genome-build TS_CPP_V2
#!genome-build-accession NCBI_Assembly:GCF_016801865.2
#!annotation-source NCBI RefSeq GCF_016801865.2-RS_2022_12
NC_068937.1     Gnomon  gene    2046    110808  .       +       .       gene_id "LOC120427725"; transcript_id ""; db_xref "GeneID:120427725"; description "homeotic protein deformed"; gbkey "Gene"; gene "LOC120427725"; gene_biotype "protein_coding"; 
NC_068937.1     Gnomon  transcript      2046    110808  .       +       .       gene_id "LOC120427725"; transcript_id "XM_052707445.1"; db_xref "GeneID:120427725"; gbkey "mRNA"; gene "LOC120427725"; model_evidence "Supporting evidence includes similarity to: 25 Proteins"; product "homeotic protein deformed, transcript variant X3"; transcript_biotype "mRNA";

The last two lines of the snippet above are the first rows of the tabular part. There is no line with column names, so here’s the snippet with aligned columns and added column names also shown in the lecture:

seqname       source  feature     start   end     score  strand  frame    attributes
NC_068937.1   Gnomon  gene        2046    110808  .       +       .       gene_id "LOC120427725"; transcript_id ""; db_xref "GeneID:120427725"; description "homeotic protein deformed"; gbkey "Gene"; gene "LOC120427725"; gene_biotype "protein_coding"; 
NC_068937.1   Gnomon  transcript  2046    110808  .       +       .       gene_id "LOC120427725"; transcript_id "XM_052707445.1"; db_xref "GeneID:120427725"; gbkey "mRNA"; gene "LOC120427725"; model_evidence "Supporting evidence includes similarity to: 25 Proteins"; product "homeotic protein deformed, transcript variant X3"; transcript_biotype "mRNA"; 
NC_068937.1   Gnomon  exon        2046    2531    .       +       .       gene_id "LOC120427725"; transcript_id "XM_052707445.1"; db_xref "GeneID:120427725"; gene "LOC120427725"; model_evidence "Supporting evidence includes similarity to: 25 Proteins"; product "homeotic protein deformed, transcript variant X3"; transcript_biotype "mRNA"; exon_number "1"; 
NC_068937.1   Gnomon  exon        52113   52136   .       +       .       gene_id "LOC120427725"; transcript_id "XM_052707445.1"; db_xref "GeneID:120427725"; gene "LOC120427725"; model_evidence "Supporting evidence includes similarity to: 25 Proteins"; product "homeotic protein deformed, transcript variant X3"; transcript_biotype "mRNA"; exon_number "2";

Some details on what’s in each column:

Column # Column ID Explanation
1 seqname Name of the chromosome, scaffold, or contig
2 source Name of the program that generated this feature, or the data source (e.g. database)
3 feature Name of the feature type, e.g. “gene”, “exon”, “intron”, “CDS”
4 start Start position of the feature (sequence numbering starts at 1; start position is included)
5 end End position of the feature (end position is also included)
6 score A confidence score for the feature, often absent (in which case it is .)
7 strand Whether the feature is on the + (forward) or - (reverse) strand1.
8 frame 0, 1 or 2 (or . for no frame). E.g. 0 means the first base of the feature is the first base of a codon
9 attributes A semicolon-separated list of key-value pairs with additional information. Can be very wide!

Exercise 2: Exploring the GTF annotation file

Before you start, make you sure you have read the box “GTF file info for this week’s exercises” at the bottom of the page for this week’s second session.

  1. Create a dir week03/ex2 within your personal dir3, and navigate there.

  2. Copy the genome annotation file garrigos-data/ref/GCF_016801865.2.gtf.gz to a file called annot.gtf.gz inside your ex2 working dir.

  3. Check the size of the annot.gtf.gz file. Then, unzip (decompress) the GTF file with the gunzip command as shown below. Finally, check the size of the resulting annot.gtf file. How large is the size difference between the compressed and uncompressed files?

    gunzip annot.gtf.gz

  4. How many lines does the GTF file contain?

  5. The total number of features in a GTF file is simply the number of lines in its table.

    • Combine grep -v and wc -l to count the number of features. (First, you may want to take a peek at the file with less -S to decide on a search pattern for grep.)

    • Comparing the linecount from this and the previous exercise, does the difference reflect the number of header lines?

    • If not, can you figure out which other line(s) contain the pattern you used with grep above? (Review the “Additional grep tips” box in the section on grep to find an option that might help you make sense of that.)

  6. How many distinct “sequences” (chromosome/scaffolds/contigs) are represented in the annotation?

    Click here for a hint

    In this and all following questions, you’ll only want to consider the table part of the file, so you should start your commands with grep -v as above.

  7. Store a list of these distinct sequences in the GTF in a file scaffolds.txt.

  8. Print a “count table” (like we did towards the end of this section) of feature types in the annotation: i.e. for each feature type, generate a count representing the number of times it occurs. This will allow you to see, for example, how many genes have been annotated in this genome.

  9. For a gene of interest, you may wonder how many exons and other annotated features it has. GTF files have an implicit hierarchical structure, where e.g. each exon row contains a reference to the gene it is a part of (its “parent”) in the final column. For gene LOC120427725, print a count table of its feature types. (You can assume that this gene’s name does not occur in any lines describing features that are not part of the gene.)

  10. Bonus: Produce a 3-column table with the sequence name, start position, and end position of each distinct start codon in the GTF file. Store that table in a file start_codons.tsv. (You can assume that the string start_codon occurs only in the third column, so that all lines with that string contain start codon features.)

  11. Bonus: In this genome, which sequence (chromosome/scaffold/contig) appears to be the largest one?

    Click here for a hint

    This information is not directly contained in this GTF file, but if you are able find the highest number in the (start or) end coordinate column, and check which sequence that is on, you should get the correct answer.

    To do this, you need to first cut the relevant columns, and then sort specifically by the coordinate column (using the -k option).

  12. Bonus: Count the number of small nuclear RNAs (snRNA) in the annotation. You’ll want a “gene”-level count (i.e. a count of the number of gene features annotated as snRNA), but because the word “snRNA” also occurs for other features, the search pattern snRNA would not work. An initial grep search would help to find a good final search pattern — to spare you that trouble, it should be: gene_biotype "snRNA". But this poses another challenge: the pattern contains double quotes ("), which we’ve been using to indicate where the search pattern begins and ends.

    Click here for a hint

    Use single quotes (') instead of double quotes around the entire pattern.

Exercise 3: Exploring the FASTQ files

For all questions below except the Bonus question, use the FASTQ file ERR10802863_R1.fastq.gz. Also, keep in mind that the file is compressed, and operate on the compressed file directly (don’t decompress it).

  1. Navigate into the dir with FASTQ files from the Garrigos et al. data.

  2. How many reads does the file contain?

    Click here for a hint

    A linecount of the compressed file will not give you the correct answer. Therefore, use the zcat <file.gz> | <...> idiom instead.

    Also, remember that one read covers 4 lines and that FASTQ files only contain lines with reads.

  3. How many reads contain the sequence ACGT? (You can assume that this does not occur in the sequence quality lines.)

  4. Using the read length information in the FASTQ header lines, print a count table of read lengths.

    Click here for some hints

    • First you need to select only the header lines. When doing so, you can assume that no @s occur in the other lines.

    • Next, you’ll need to extract / single out the read length numbers in these header lines, which are in the format length=74. One way to do this is a fun trick: by using = as the delimiter (-d option) to cut!

  5. Count the number of reads that contain at least 10 consecutive Ns, i.e. uncalled bases. (You can assume that stretches of N’s do not occur in the sequence quality lines.)

  6. Compare the number you got in the previous question, with the number of 35-bp reads from the question before that. What does this seem to tell you? To confirm, can you check what a sample of 35-bp reads look like?

    Click here for a hint

    With grep -A1, you can print the line after each match. This will allow you to see the sequences in the 35-bp reads. Pipe to less or head so you don’t get thousands of lines printed to screen.

  7. Bonus: Can you find out, with a single command, what the total number of reads across all R1 files is?

    Click here for a hint

    Use zcat with a globbing (file selection) pattern with a * to operate on all R1 files at once – then pipe that into the familiar line counting command.

Exercise 2

1. Create a new dir and navigate there 
# (You should already be in /fs/ess/PAS2880/users/$USER/)
cd /fs/ess/PAS2880/users/$USER/week03
mkdir ex2
cd ex2
2. Copy the genome annotation file garrigos-data/ref/GCF_016801865.2.gtf.gz 
cp ../ref/GCF_016801865.2.gtf.gz annot.gtf.gz
3. Unzip (decompress) the GTF file

  • Check the file size:

    ls -lh
    -rw-rw----+ 1 jelmer PAS0471 5.1M Jul 14 18:55 annot.gtf.gz

  • Unzip:

    gunzip annot.gtf.gz

  • Check the file size (and name) again:

    ls -lh
    -rw-rw----+ 1 jelmer PAS0471 123M Jul 14 18:55 annot.gtf

  • That’s a pretty big difference, from 5.1 Mb to 123 Mb! The amount of space saved by file compression varies a lot and depends on the amount of repetition in the uncompressed file. GTF files are highly repetitive, so relatively much space can be saved.

4. How many lines does the GTF file contain?

A simple line count tells you that the file has 408,402 lines:

wc -l annot.gtf 
408402 annot.gtf
5. Count the number of line in the GTF table.

  • Since the header lines contain a #, you’ll want to exclude those and then count the remaining number of lines:

    grep -v "#" annot.gtf | wc -l
    408397

  • The file has only 4 header lines, while the line count has decreased by 5 (from 408402 to 408397). So, which other line in the file has a #?

    Use the -n option to grep to print line numbers along with each match:

    grep -n "#" annot.gtf
    1:#gtf-version 2.2
2:#!genome-build TS_CPP_V2
3:#!genome-build-accession NCBI_Assembly:GCF_016801865.2
4:#!annotation-source NCBI RefSeq GCF_016801865.2-RS_2022_12
408402:###

    So, it looks like the very last line also has a #: it is simply ###, functioning as an end-of-file marker.

6. How many distinct sequences are represented in the annotation?
  • Make sure to first exclude the header lines with grep -v
  • The first column contains the sequence name (cut -f 1)
  • To only keep distinct sequences, use sort | uniq
  • To get a count of the resulting list of distinct sequences, use wc -l.
grep -v "#" annot.gtf | cut -f 1 | sort | uniq | wc -l
167
7. Store a list of distinct sequences in the GTF in a file scaffolds.txt.

  • Same command as above, but we get rid of wc -l and instead redirect the output of uniq to a file:

    grep -v "#" annot.gtf | cut -f 1 | sort | uniq > scaffolds.txt

  • Take a peek at scaffolds.txt for a sanity check:

    head -n 3 scaffolds.txt
    NC_015079.1
NC_068937.1
NC_068938.1
9. Produce a “count table” of feature types in the annotation
  • The feature type is in the third column (cut -f 3)
  • To produce a count table, use the sort | uniq -c idiom.
grep -v "#" annot.gtf | cut -f 3 | sort | uniq -c
 141444 CDS
 166177 exon
  19673 gene
  25864 start_codon
  25892 stop_codon
  29347 transcript
9. Print a count table of annotated features for gene LOC120427725 
grep "LOC120427725" annot.gtf | cut -f 3 | sort | uniq -c
     15 CDS
     20 exon
      1 gene
      3 start_codon
      3 stop_codon
      3 transcript
10. Print a start codon genomic coordinate table

  • After greping for start_codon, you need to select (cut) the first, fourth, and fifth columns.

  • Taking a peek at the output, it appears that start codons may duplicated:

    grep "start_codon" annot.gtf | cut -f 1,4,5 | head -n 5
    NC_068937.1     70143   70145
NC_068937.1     70143   70145
NC_068937.1     70143   70145
NC_068937.1     49062   49064
NC_068937.1     160735  160737

    This is because distinct transcripts of a gene (producing different isoforms) may share the same start codon.

  • To get rid of the duplicates, use sort | uniq — and then we can redirect the output to start_codons.tsv:

    grep "start_codon" annot.gtf | cut -f 1,4,5 | sort | uniq > start_codons.tsv

  • Take a peek at the output file for a sanity check:

    head -n 5 start_codons.tsv
    NC_015079.1     10427   10429
NC_015079.1     12600   12602
NC_015079.1     211     213
NC_015079.1     3055    3057
NC_015079.1     3898    3900
11. Which sequence (scaffold) appears to be the largest one?
  • You’ll want to reverse (-r) numerically (-n) sort by the (fourth or) fifth column.
  • To only get the feature with the largest end position, add head -n 1
  • (We could add | cut -f 1 to only get the sequence name, not the entire line.)
grep -v "#" annot.gtf | sort -k5nr | head -n 1
NC_068938.1     Gnomon  exon    224093433       224093803       .       +       .       gene_id "LOC120429120"; transcript_id "XM_039594310.2"; db_xref "GeneID:120429120"; experiment "COORDINATES: polyA evidence [ECO:0006239]"; gene "LOC120429120"; model_evidence "Supporting evidence includes similarity to: 6 Proteins"; product "caprin homolog"; transcript_biotype "mRNA"; exon_number "4";
  • So the largest sequence appears to be NC_068938.1.
12. Count the number of snRNAs in the annotation.

Because the search pattern itself contains double quotes ("), the easiest way out is to use single quotes (') around it:

grep -c 'gene_biotype "snRNA"' annot.gtf
58

6. What’s up with the 35-bp reads?

The number of reads with at least 10 consecutive Ns (32,612 – previous question) is rather close to the number of 35-bp reads (32,678 – question before that). Might nearly all 35-bp reads consist of mostly or only Ns?

One way to see a sample of 35-bp reads is by using greps -A option to also print the line after each match:

zcat ERR10802863_R1.fastq.gz | grep -A1 "length=35" | head -n 20

They do! Note that this makes some sense because the target length of these reads is 75 bp. Read length variation in Illumina reads is usually very minor, with >99% of reads typically being up to 1 or bases from the target base length. As such, these 35-bp reads are unusual to begin with, and it may not be entirely surprising that they are of very poor quality.

7. What is the total number of reads across all R1 files?

We can use zcat with a * wildcard pattern to print the contents of all R1 files, and simply perform a line count on that:

zcat *_R1.fastq.gz | wc -l
44000000

So, the total number of reads is 44,000,000 / 4 = 11,000,000. This makes sense because we have 22 R1 FASTQ files, each of which has 500 k reads.
