1 Introduction

1.1 Learning goals

In this session about (bioinformatics) software management at OSC and beyond, you will learn:

  • How to find and load OSC “modules” to use specific programs
  • Why containers and Conda are useful and reproducible alternative ways to use software
  • How to find and run Apptainer/Singularity containers to use specific programs
  • What the program FastQC does and how you can run it

2 Software management (at OSC)

To analyze omics data sets, especially in genomics and transcriptomics, a typical workflow includes running a sequence of specialized bioinformatics software/programs/tools (I will use these terms interchangeably).

At OSC, there are system-wide installations of a number of bioinformatics programs. We do need to “load modules” containing such programs before we can use them. In this session, we will first talk about that process.

However, OSC’s collection of bioinformatics programs is not comprehensive, and the most recent versions are often not available1. On top of that, installing software the way you are used to on your own computer is not really possible at a supercomputer center like OSC.

We therefore need an additional way to use bioinformatics programs at OSC. Two common ones are:

  • Containers, which are self-contained software environments that include operating systems, akin to mini virtual machines. Docker containers are most well-known, but supercomputers like OSC use Apptainer (formerly known as Singularity).

  • The Conda software management program, which installs software and its dependencies in “environments” that you can load.

Conda and containers are useful:

  • Specifically at supercomputers like OSC, where they bypass issues with “dependencies”2 and “administrator privileges”3 that you may run into when trying to install software in other ways.

  • More generally for reproducible software environments.

  • Because they make it easy to switch between different versions of the same software, or to use mutually incompatible software.

In this session, you will learn how to obtain and use containers, while this optional-reading page covers Conda.

Other options to install software / get it installed at OSC

  • Send an email to OSC Help. They might be able to help you with your installation, or in case of commonly used software, might be willing to perform a system-wide installation (that is, making it available through Lmod / module commands).

  • “Manually” install the software, which in the best case involves downloading a directly functioning binary (executable), but more commonly requires you to “compile” (build) the program. This is sometimes straightforward but can also become extremely tricky, especially at OSC where you don’t have administrator privileges and will often have difficulties with dependencies.

2.1 The FastQC software

As an example piece of bioinformatics software, we will use FastQC (Andrews (2010)) in this session.

FastQC is a ubiquitous tool for quality control of FASTQ files. Running FastQC or a similar program is the first step in nearly any high-throughput sequencing project. FastQC is also a good introductory example of a tool with a command-line interface.

For each FASTQ file, FastQC outputs an HTML file that you can open in your browser with about a dozen graphs showing different QC metrics. The most important one is the per-base quality score graph:


3 Loading software at OSC with Lmod modules

OSC administrators manage software with the “Lmod” system of software modules. This means that a lot of installed software can only be used after its module is explicitly loaded. That may seem like a drag, but on the upside, this practice enables the use of different versions of the same software, and of mutually incompatible software on a single system.

We can load, unload, and search for available software modules using the module command and its sub-commands.

Not all software has to be loaded

Not all software has to be loaded: besides all the basic Unix commands we have been using, very widely used software like Git, Python, and Apptainer is available to us without loading anything.

3.1 Checking whether a piece of software is available

The OSC website has a list of installed software. You can also search for available software in the shell using two subtly different module commands:

  • module spider lists all installed modules.
  • module avail lists modules that can be directly loaded given the current environment (i.e., when taking into account which other software has been loaded, which can make a difference).

Simply running module spider or module avail spits out complete lists of installed/available programs — it is therefore more useful to add a search term as an argument. For example, try to use module spider to search for fastqc:

module spider fastqc
--------------------------------------------------------------------------------
  fastqc: fastqc/0.12.1
--------------------------------------------------------------------------------

    This module can be loaded directly: module load fastqc/0.12.1

    Help:
      A quality control tool for high throughput sequence data.

We can see that fastqc is available, namely version 24.10.4 (that is, the module is printed as <software>/<version>).

These two search commands are not case-sensitive (but module load -below- is)

3.2 Loading modules

All other Lmod software functionality is also accessed using module commands. For instance, to make a program available to you, use the load command.

But first, let’s confirm that it is not possible to use FastQC before doing so:

  • The command to run FastQC is fastqc
  • Like Unix commands, fastqc has many options, and we can pass FASTQ files as arguments.
  • For our inital tests, we will simply run fastqc -v, which should print the FastQC version if the command is available.
fastqc -v
bash: fastqc: command not found...
Failed to search for file: GDBus.Error:org.freedesktop.DBus.Error.NameHasNoOwner: Could not activate remote peer.

Now, load the module — specify the module name and its version exactly as module spider printed it:

module load fastqc/0.12.1

And then check whether we can use FastQC once again:

fastqc -v
FastQC v0.12.1

Success!

When to use module load

Note that module loading does not persist across shell sessions. Whenever you get a fresh shell session (including but not limited to after logging into OSC again), you will have to reload any modules you want to use!

When you run a program that is loaded with Lmod in your shell script, always include the module load command in the script, and it is best to do so at the top of the script – for example:

#!/bin/bash
set -euo pipefail

# Load software
module load fastqc/0.12.1

Here, we only covered the very basics of using module. To learn a bit more, you can read the boxes below, but in class, we will not go into further detail because we will mostly use containers instead. (considering the limitations of these modules and the advantages of containers discussed above).

4 Using Apptainer containers

Containers are similar to Virtual Machines, and different from Modules and Conda environments, in that they come with an entire operating system.

That may seem a bit much, but it makes them particularly portable (likely to work across computing environments) and using containers improves the reproducibility of your research. This is particularly true if you use publicly available containers as we will do. It’s also easier in a way, because you don’t need to install anything: you will select a container that has the desired software installed, and will then simply use that container directly.

Among container platforms, Apptainer (formerly known as Singularity) and especially Docker are the most widely used ones. At supercomputers like OSC, however, only Apptainer containers can be used4. Some Apptainer container terminology:

  • Container image: a binary file that contains the container application (.sif extension)
  • Container (sensu stricto): a running container image
  • Definition file: a plain text file that contains the recipe to build a container image

Here, you will learn how to find container images online and use them at OSC. We will not cover writing Definition files to create your own custom containers, as this is very rarely needed especially given recent developments in online container availability (covered below).

4.1 Quick overview of using containers

The first step to using a container is obtaining it: you’ll see below how to get a link for a container that is available online. Similar to when you install software, obtaining the container is one-time thing: once you use or explicitly download it, the container image will remain until you remove it.

The second step is to run an appropriate command to access the desired software that is installed inside the container. To run a command in a container, the general syntax is:

  • When referencing a .sif container image on your computer:

    apptainer exec <my-container.sif> <command>

  • When directly referencing a container image online (yes, this is possible!):

    apptainer exec <URL> <command>

This means that if the command we want to run is fastqc -v, and we had a container image file fastqc.sif…

  • Instead of running:

    fastqc -v

  • You would run:

    apptainer exec fastqc.sif fastqc -v

    So, you just need to preface your “regular” command with apptainer exec <sif/URL>.

4.2 Obtaining a container image

Several online repositories have publicly available container images, but I strongly recommend Seqera Containers.

Seqera Containers

Seqera Containers is currently the most reliable site with containers, and it is actually more than just a repository: when a container with the program(s) you request is not available in the repository, it will build the container for you. So, it allows you to select:

  • Any version of software that’s available
  • Any combination of software that’s not mutually incompatible

Then, it will see if a container with your exact requirements is already available and if not, it will build it and make it available.

Getting a container, step-by-step

Here is a step-by-step procedure to get a container — we will again use FastQC version 0.12.1 as the example, but the procedure would be the same for any other program that’s available:

  1. Go to https://seqera.io/containers.

  2. In the search box below “Containers”, enter fastqc.

  3. After waiting for the list to populate, the top hit should be bioconda::fastqc, with version 0.12.1 selected (the most recent version is always selected by default).

  4. Add FastQC to your “container request” by clicking the blue + Add button. At this point, you could add additional programs, but here, we are happy with creating/fetching a container that only has FastQC.

  5. In “Container settings” below the search box, change from Docker to Singularity (and leave the other dropdown as is – linux/amd64 should be selected).

  6. Get a link to the container image by clicking the blue Get Container button.

  7. Copy the link to the container image that should appear immediately In this case, the link should be: oras://community.wave.seqera.io/library/fastqc:0.12.1--104d26ddd9519960.

4.3 Running a container image

To recap, running a program in a container is done with a command that basically consists of two parts:

  1. apptainer exec <URL> (or apptainer exec <my.sif>) followed by
  2. the “regular” command, e.g. fastqc -v

Let’s check that we can run FastQC in the container:

apptainer exec oras://community.wave.seqera.io/library/fastqc:0.12.1--104d26ddd9519960 \
  fastqc -v
INFO:    Downloading oras image
384.0MiB / 384.0MiB [======================================================================================================================] 100 % 51.8 MiB/s 0s
INFO:    gocryptfs not found, will not be able to use gocryptfs
FastQC v0.12.1
Breaking up a command across lines with \

Above, I broke the command up across two lines, which can be done by ending the first line with a \. This helps with readability for long commands like this one. It also makes particular sense here given the “two-part structure” of the command discussed above.

The first time you run this command, the container image will be downloaded to a default location (see box below), as you can see in he output above — this will take a minute or so.

When rerunning the same command, Apptainer will realize that the container image has already been downloaded and will automatically use the downloaded version:

apptainer exec oras://community.wave.seqera.io/library/fastqc:0.12.1--104d26ddd9519960 \
  fastqc -v
INFO:    Using cached SIF image
INFO:    gocryptfs not found, will not be able to use gocryptfs
FastQC v0.12.1

(You will keep seeing the gocryptfs not found message, but this is nothing to worry about.)

The container image cache

(by default it will be downloaded to ~/.apptainer/cache, but you can change this by setting the $APPTAINER_CACHEDIR environment variable).

4.4 Running FastQC

To analyze a FASTQ file with default FastQC settings, the command would simply be fastqc followed by the FASTQ file path – and we could use on of the FASTQ files in our Garrigos practice data set:

# [Don't run this]
apptainer exec oras://community.wave.seqera.io/library/fastqc:0.12.1--104d26ddd9519960 \
  fastqc ../garrigos-data/fastq/ERR10802863_R1.fastq.gz

However, an annoying default behavior of FastQC is that it writes its output files in the same dir that contains the input FASTQ files — this means mixing your raw data with your results, which we don’t want!

Changing the output directory?

To figure out how to change that behavior, consider that many standard Unix commands and bioinformatics tools alike have an option -h and/or --help to print usage information to the screen. Let’s try that:

apptainer exec oras://community.wave.seqera.io/library/fastqc:0.12.1--104d26ddd9519960 \
  fastqc -h
INFO:    Using cached SIF image
INFO:    gocryptfs not found, will not be able to use gocryptfs

            FastQC - A high throughput sequence QC analysis tool

SYNOPSIS

        fastqc seqfile1 seqfile2 .. seqfileN

    fastqc [-o output dir] [--(no)extract] [-f fastq|bam|sam] 
           [-c contaminant file] seqfile1 .. seqfileN

DESCRIPTION

    FastQC reads a set of sequence files and produces from each one a quality
    control report consisting of a number of different modules, each one of 
    which will help to identify a different potential type of problem in your
    data.

The option to do this is -o/--outdir:

fastqc -h
  -o --outdir     Create all output files in the specified output directory.
                    Please note that this directory must exist as the program
                    will not create it.  If this option is not set then the

The final command

With the added --outdir (or -o) option, try to run the following FastQC command:

# We'll have to first create the outdir ourselves, in this case:
mkdir -p results/fastqc

# Now we run FastQC:
apptainer exec oras://community.wave.seqera.io/library/fastqc:0.12.1--104d26ddd9519960 \
  fastqc --outdir results/fastqc ../garrigos-data/fastq/ERR10802863_R1.fastq.gz

Specifying an output dir vs. output file(s)

FastQC allows us to specify the output directory, but not the output file names: these will be automatically determined based on the input file name(s). This kind of behavior is fairly common for bioinformatics programs, since they will often produce multiple output files.

Closing notes

It is preferable to instead write small scripts to run such programs and then submit those scripts as so-called “batch jobs” at OSC.
